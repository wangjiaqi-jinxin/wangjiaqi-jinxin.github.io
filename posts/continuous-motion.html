连续机器人运动为什么仍会卡顿：从离散 Servo 到在线接管

位置连续并不意味着运动连续。真正决定体验的，是离散控制周期内的位置、速度、加速度与 Jerk 能否一起衔接。

离散控制的边界

机器人控制器通常不会直接执行一条“连续函数”，而是在固定 Servo 周期内消费离散点列。设采样周期为 Δt，关节位置为 qₖ，则控制层实际看到的速度、加速度和 Jerk 分别近似为：

vₖ = (qₖ − qₖ₋₁) / Δt　　aₖ = (vₖ − vₖ₋₁) / Δt　　jₖ = (aₖ − aₖ₋₁) / Δt

这意味着：即使两段轨迹在数学上“看起来相连”，只要新段的第一帧没有匹配上一段末帧的速度和加速度，除以一个很小的 Δt 后仍会出现尖峰。视觉上的卡顿往往不是位置断裂，而是速度归零、加速度突变，或 Jerk 超限后被安全策略迫使减速。

S 曲线不是万能药

Jerk 受限的 S 曲线能让独立点到点运动更平滑。它会经历加 Jerk、恒加速度、减 Jerk、巡航和对称减速等阶段；当位移不足时，峰值速度还需要主动削减。

但如果每个上层离散点都被规划成“末速度为零”，结果仍是：加速 → 到点 → 停止 → 再加速。对喷涂、打磨等连续工艺而言，内部点需要允许继承非零末速度；同时还要把总时长对齐到 Servo 周期的整数倍，避免最后出现极短尾帧，被错误地按完整周期计算动力学。

在线接管为何选未来点

运行中收到新目标时，不能简单从“此刻反馈位置”重规划。新命令到达、规划完成、队列真正替换之间仍有延迟；如果机器人在这段时间继续前进，新轨迹的起点就已经落后于真实执行状态。

更稳妥的做法是选择尚未下发的未来边界点作为 SwitchPoint，并继承该点完整的 PVA 状态：位置、速度和加速度。随后保留旧队列直到这个边界，再将之后的未来点替换为新轨迹。若消费者已经越过边界，就应拒绝拼接并重新选择，而不是把轨迹硬接到错误状态。

C² 连续与几何保持

五次多项式有六个系数，正好能约束起点和终点的 P、V、A，因此适合构造 C² 连续过渡。但 C² 连续不代表 Jerk 自动合格，也不代表 TCP 仍沿着工艺直线。

对 MoveL 这类必须保持几何直线的运动，更可靠的思路是沿直线比例 r(t) 做时间重参数化：

p(t) = p₀ + r(t) · (p₁ − p₀)，　0 ≤ r(t) ≤ 1

只有当 r(t) 单调推进时，TCP 才会留在同一条直线上；每个离散比例再经过逆解转换为关节点。相比直接在关节空间套五次曲线，这能避免“关节很平滑、喷枪却偏离工艺线”的问题。

先验证，再回退

连续规划不应只有一种算法。实践中可按风险从低到高尝试：同向队尾追加、共线直拼、笛卡尔过渡、整段重定时、关节空间过渡；每个候选都要检查关节和 TCP 两侧的速度、加速度、Jerk 与几何误差。

失败时安全软停并不等于算法失败，它是拒绝不可执行边界的最后防线。更重要的是记录最终采用的策略、被拒绝原因和真实执行时长。这样下一次优化针对的是证据，而不是盲目放宽阈值。
